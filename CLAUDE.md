# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## Never commit real 2FA data

This repository is public and git history is permanent. A Google Authenticator
export QR code is the full credential for every account inside it: anyone who
has it can generate those codes indefinitely, and changing the account password
does not revoke it.

So, without exception:

- No real `otpauth-migration://` string, in any file, comment, test, README,
  issue or pull request description.
- No real base32 secret, no screenshot of a real export code.
- No "temporary" commit that is reverted later. The reflog keeps it.

Every fixture under `tests/fixtures/` is generated by
`scripts/generate-fixtures.ts` from hard-coded synthetic inputs (RFC test keys,
byte ramps, hashed placeholders) and verified by SHA-256 in CI, so a hand-added
file fails `pnpm fixtures:verify` before it can reach a release. There is also a
shape guard (`tests/security/no-real-secrets.test.ts`) and a gitleaks job.

If the protobuf schema ever needs re-confirming against a real export, do that
work in a directory outside this repository. `scratch/` is gitignored for
exactly this.

Error messages must never interpolate secret material, and the diagnostics panel
logs timings and ladder rungs, never payload bytes.

## What this is

A zero-runtime-dependency package that turns a Google Authenticator "Export
accounts" QR code into `otpauth://` URIs and base32 secrets, entirely in the
browser. It ships three things: a library, a DOM/camera adapter layer, and a
single-file offline HTML app that works from `file://` with the network off.

The offline HTML is the flagship deliverable, not a demo. It is what makes the
privacy claim checkable rather than something a reader has to believe.

## Rules that are not obvious from the code

**Zero runtime dependencies.** `"dependencies": {}` is written out explicitly so
an accidental addition shows up in a diff, and CI asserts the count is zero.
devDependencies are fine.

**Never use `URL` or `URLSearchParams` to read the `data` parameter.**
`URLSearchParams` applies form-urlencoded decoding, which turns a _literal_ `+`
into a space. The payload is standard base64, so it contains `+`.

Both forms occur. Google Authenticator's own QR codes percent-encode it as
`%2B`, and those happen to survive URLSearchParams. But a literal `+` is legal
in a query string and shows up whenever the URI has been relayed by another
tool, pasted by hand, or produced by something that did not encode it, and those
are destroyed: either a base64 error, or a silently wrong secret that generates
codes which never work.

Extract with a regex and run `decodeURIComponent` on the capture only. That is
correct for both forms, because `decodeURIComponent` leaves a literal `+` alone
and still resolves `%2B`. See `tests/encoding/base64.test.ts`, "the plus-sign
hazard"; do not "clean up" the parser past it.

**`EC_INDEX` and `EC_FORMAT_BITS` are different mappings.** QR block tables are
ordered L, M, Q, H. The two bits written into the format information are ordered
M, L, H, Q. Conflating them is the most common QR implementation bug and it
fails only for some error-correction levels, so it survives casual testing.

**Pure parsers throw; attempt-shaped operations return `Result`.** "No QR in this
camera frame" happens thirty times a second and must not allocate a stack trace.

**`src/qr/**` imports nothing outside itself** except `../errors.js`, enforced by
ESLint. It is about two thirds of this package and has nothing to do with Google
Authenticator, so it stays liftable into its own package.

**No Web Worker in this package.** Blob workers are blocked under `file://` in
Chrome, and the offline HTML has to work there. Consumers that want a worker
wrap the pure decode function in one themselves, which is what the website does.

**The migration payload has no period field.** Google Authenticator is fixed at
30 seconds. `OtpAccount.period` is therefore always 30 and carries
`periodSource: 'google-default'` beside it, so nobody mistakes it for decoded
data. The same honesty applies to unspecified algorithm and digit enums, which
is what `defaultsApplied` records.

**No top-level DOM or Node access in `src/` outside `src/dom/` and `src/app/`.**
hex-web bundles this into a server-side render, and a top-level `document` would
throw at import.

## Adding a feature

The QR decoder deliberately does not support Micro QR, rMQR, structured append,
FNC1/GS1, or multiple symbols in one image. Google's multi-QR export is handled
at the payload level by `BatchCollector`, one symbol per image or frame. These
are refusals with clear error messages, not gaps waiting to be filled. Widening
the scope means widening the test surface of a security tool; make the case
before writing the code.

## Style

Tabs. Single quotes. Named exports, no default exports. `.js` extensions on
relative imports (NodeNext). Explicit `import type`. Comments explain why, not
what. Australian English in prose.

No em dashes or en dashes as prose punctuation, no decorative emoji, and none of
the usual marketing register ("unlock", "seamless", "robust", "empower",
"effortless", "leverage" as a verb). This applies to the README, the standalone
app's UI copy and error messages, which are all user-facing.
